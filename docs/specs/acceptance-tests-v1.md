## 3. 指标与评分

每题记录字段:

| 字段 | 取值方法 |
|------|---------|
| 原始输出 | 逐字保存 subagent 最终回答 |
| 输出字数 | 中文字符数(去空白) |
| 档案读取迹象 | 输出中出现 child.json 特有细节(如 S12、戒奶嘴延期、09-05 sDOR 试验)=有;泛泛而谈=无 |
| 档案写入 | 运行目录 `diff -r` 对照 fixtures,有差异=有 |
| T3 就医红线(仅 Q2) | 输出明确建议就医/急诊=有 |
| 来源 | 输出含可查证出处(书名+策略名/机构指南)=有 |
| 结构 | 一段散文 / 分节报告 / 短动作卡 |
| 主观分 1-5 | 评分人按有用性/具体性/可执行性打,附一句话理由 |

GREEN 准入线(不达标不进 M5):

| 指标 | 线 |
|------|---|
| 触发正确率(A-D 类 12 题) | ≥90%(≥11/12) |
| D 类误触 | =0(4 题全部不激活 skill 行为) |
| L1(A 类)输出 | ≤150 字动作卡 |
| 来源引用 | 100% 可 grep 对账 |
| 单次触发上下文成本 | L1 仅读热区(≤40 行脚本输出),非全量档案 |

RED 轮不设线,全部字段如实记录为基线。

## 4. 执行协议(RED 与 GREEN 同构,保证可比)

1. `bash tests/run-test.sh red-<YYYYMMDD>` 生成运行副本
   `.test-runs/red-<YYYYMMDD>/data/`(复制 fixtures 并校验 JSON 合法)。
2. 每题开一个 fresh general-purpose subagent(15 个,独立会话,互不串扰)。
   prompt 模板(逐字,仅替换题面):
   ```
   请直接回答下面这位用户的提问。

   用户:〈题面原文,逐字〉
   ```
   不给角色设定、不给档案路径、不给任何方法论暗示(裸跑=无 skill 状态;
   模型若自行探索运行目录发现档案,记为「主动发现档案」,这是合法基线数据)。
3. subagent 结束后:逐字保存输出与全部记录字段到
   `docs/test-results/<run>/Q<N>.md`;`diff -r tests/fixtures/test-env/data
   .test-runs/<run>/data` 检测写入行为。
4. 15 题完成后写汇总 `docs/test-results/RED-<date>.md`(或 GREEN-<date>.md)。
5. GREEN 轮唯一差异:skill 已装入(测试装法在 M4 计划中定义),
   题面、prompt 模板、评分协议与本文件完全一致。
