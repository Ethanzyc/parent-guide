# 知识蒸馏 SOP(SSOT)

> 定位:蒸馏流程的**单一事实来源**(2026-10-09 定稿,用户拍板:建 skill=
> `distill`,SSOT=本文件)。`skills/distill/` 是调度层,knowledge-index §5
> 保留触发协议并指向这里。沉淀自两轮实战:2026-09-29 首测(tantrum-cdc.md,
> CDC 公有领域)与 2026-10-04 语料吸收(weaning/toilet,疑点引用弃用 6 处)。

## 0. 一句话定位

蒸馏=**把外部材料(书/文献/讲座/语料/公有领域资源)加工成本库格式的知识
文件**。输入永远是外部材料;输出进知识库,按版权与审核等级分两个落位;
知识库自身内容不是蒸馏对象。

## 1. 输入与输出落位

- 输入三类:①家长/维护者提供的材料(书章节/文献/长视频文稿)②语料源
  (如 yuer 公开口径,子代理提取,剔除个人信息)③公有领域资源(如 CDC
  家长课程)。
- 输出落位(与缺口调研补全同体系):

| 材料性质 | 落位 | 审核等级 |
|---|---|---|
| 版权受限(书籍等) | `knowledge/user/`(自建层,头部「自建:」三要素行) | 轻审(来源真实性+关键数字回溯) |
| 公有领域/公开口径 | `knowledge/` 根目录(官方闭集,check-knowledge+publish 双侧登记) | 四件套(含引用全审)+用户拍板 |

## 2. 方法(仓颉.Skill 精髓+本库改造规则)

- 仓颉精髓(自 2026-09-29 首测引用):RIA-TV 式提炼/「只有很小部分内容配
  成为工具」/触发+边界/execution-oriented;
- 本库改造规则(产物必须全部满足):
  1. **陈述性知识+口径**,不是触发式技能——reference 形态(是什么/底线
     数字/分级/就医线),不是 how-to 指令堆;
  2. **防重复**:开蒸前扫描官方库+自建层同主题文件;重复内容淘汰,产物
     头部留「防重复蒸馏清单」(首测实证:主动淘汰 3 项与官方库重复);
  3. **官方关系标注**:与官方库同主题文件逐条标(互补/一致/张力+以官方
     为准的理由),冲突不悄悄站边;
  4. **疑点引用弃用**:来源可疑(期刊标注不一致/编号待核/缺年份)一律
     不采用并记录;
  5. **三要素头部**必留(来源/日期/核对级别)。

## 3. 三种模式

| 模式 | 触发说法 | 流程差异 |
|---|---|---|
| 材料蒸馏 | 「蒸馏一下」「蒸馏这本书第 X 章」 | 材料在手→§5 流程 |
| 语料吸收 | 「吸收 XX 语料」(维护者) | 子代理提取公开口径+剔除个人信息+标注疑点引用→§5 流程 |
| BACKLOG 批量 | 「清 BACKLOG」「批量蒸馏」(维护者) | 按 BACKLOG 待补行逐主题:无来源先缺口调研(research.md 七步),有来源直接蒸馏→§5 流程→销账 |

## 4. 四件套检查(入库门)

①三要素写入;②`audit-citations.sh` 机械对账;③官方关系标注;④引用全审
——官方库目标=逐断言全审(协议见 docs/knowledge-audit-sop.md,可派
subagent);自建层目标=轻审(来源存在+关键数字回溯)。

## 5. 流程全图

材料入手 → **版权判定**(定落位)→ **防重复扫描** → 蒸馏(§2)→
四件套 → 落位(自建=user/ 直接落;官方=草案+审计结果**待用户拍板**)→
BACKLOG 销账(如有)→ 官方入库时:site 重建+audit-LOG 台账记一行。

## 6. 红线

- **书摘类永不进官方库**(版权:自用合法、分发受限);
- **未核对不入库**;
- 产物是工具不是收藏——「只有很小部分内容配成为工具」,宁缺毋滥;
- 产物须先过本 SOP,不得跳四件套直接写库。
