# 分场景输出模板

> 按分档协议选定模板后再输出。标注 strict=结构不可增删;flexible=节可按需
> 增删但顺序不变。字数以中文字符(去空白)计。

## L1 动作卡(strict,总计 ≤150 字)

结构四件,一件不少、一件不加:

1. **共情一句**(≤15 字,直接回应家长当下的处境)
2. **动作 2-3 条**(每条 ≤25 字,动词开头,一行一条;条内不解释原理)
3. **安全边界一条**(≤30 字,一句指令式:「若〈指征〉→立即就医/拨120」;
   急救手法压成一句(如「拳眼顶肚脐上方向内上冲压」),完整细节等家长追问再展开)
4. **回访钩子一行**(≤20 字)

四件之外零文字——开场白、总结、鼓励、解释、附加说明都算超字。
**输出前自查**:数中文字符(去空白),>150 就删动作条或压短安全边界文字;
禁止删安全边界这一件本身。

**共情句对照(说/不说)**:
- 不说「这很正常,别焦虑」/ 说「被围观很难熬,你没错」(先接人再接事)
- 不说「你怎么又被弄哭了」/ 说「喂到崩溃,真的太磨人了」
- 二选一要给真选项:「回家路上看小狗还是数汽车?」不说「再闹就不带你回家」

判例(2026-09-28):紧急场景输出 500+ 字=家长在哭闹现场读不完——长文即失败。

## L2 计划(flexible)

输出顺序:

1. **现状回顾**:引用 child.json 追踪区既有记录(策略 ID+回访结论),指出
   「已在做什么、效果如何」;若档案无相关记录,写「档案无相关记录」。
2. **目标**:一句话、可观察(「两周内就餐哭闹 ≤2 分钟」)。
3. **单变量**:同期只改一项;与进行中试验/策略冲突时先解决冲突再启动
   (判例 2026-09-28:零屏幕 vs sDOR 试验)。
4. **最小启动**:本周内做的 ≤3 件事,每件一行。
5. **回访点**:due 日期+看什么指标。
6. **写入追踪**:按 conversation.md 三步门把本计划落进 child.json
   (update-child.py add-strategy + add-followup),向家长复述脚本输出。

**输出后自查(四问,过不了就改完再交付)**:
1. 目标一句话、可观察?
2. 单变量:与进行中试验/策略的冲突处理了吗?
3. 回访点:due 日期+看什么指标?
4. 写入证据:脚本输出引了吗?

## L3 发育(flexible)

1. **领域逐项**:社交情感/语言/认知/动作,对照 child.json milestones 与
   knowledge-index §2 底线口径。
2. **对照结论**:已达/观察中/未出现,未出现项标注月龄正常范围。
3. **观察建议**:具体情境 1-2 个(怎么看、看什么)。
4. **T2 指征**:出现哪些信号建议专业评估(引 knowledge-index §1/§3)。

## guide 日常(flexible)

1. **活动 2-3 个**:从 child.json preferences/currentFocus 取材,标注
   「为什么适合这个孩子」一行。
2. **玩法一句**:每个活动怎么开玩。
3. **扩展提示一行**:下一步可以加什么。
不输出健康断言;涉及安全(水/小零件/高度)给一行提醒。
